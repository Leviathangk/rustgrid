# 数据传输 / 同步

`数据传输` 主标签页（`MainTab::Sync`，工具栏上位于「备份」之后）把 Navicat 的
「结构同步 / 数据同步 / 数据传输」收敛成一个工作台。它完全建立在
`rustgrid_core::{Connection, sync}` 之上：页面不认引擎，驱动能读表、读行、写行就能用。

## 页面结构

```
传输主标签 = 配置列表
┌ 新建传输 │ 编辑 │ 删除 │                         详细列表 / 平铺网格  搜索 ┐
│ 名称              源                     目标                     模式    │
│ 生产 → 预发        prod · shop            stage · shop             全部    │
└──────────────────────────────────────────────────────────────────────────┘

子窗口（新建传输 / 双击配置）
┌ 标题栏 ──────────────────────────────────────────────────────────────────┐
│ 源 [连接 ▾][库 ▾]  →  目标 [连接 ▾][库 ▾]              选择目标后开始比对 │
│ 全部 / 仅结构 / 仅数据 / 全量传输                         选项   同步(N)  │
├ 跨引擎提示条（仅当两端引擎不同） ──────────────────────────────────────┤
│ 表清单（搜索 / 全选 / 状态胶囊）  │ 检查器：结构比对 │ 数据比对 │ SQL 预览 │
├ 运行日志 + 进度条（运行或点开日志时） ────────────────────────────────┤
│ 配置名称 [____________________]                    已保存   保存配置      │
└──────────────────────────────────────────────────────────────────────────┘
```

- **配置列表**列出 `transfers.json` 中保存的传输配置（名称 / 源 / 目标 / 模式），
  与备份页一样支持搜索、排序、列宽拖动和 详细列表 / 平铺网格 切换。双击配置打开子窗口。
- **新建传输**打开子窗口并发起一次新的配置：源取连接树当前选中的库，**目标默认为空**，
  必须显式选择；未选择目标时不会自动比对。
- **子窗口**与备份窗口一样是独立 OS 窗口：标题栏、比对工作台和底部配置栏都在其中，
  关闭窗口即停止正在运行的任务。底部可命名并 `保存配置`，同名覆盖，改名即另存为。
- **表清单**列出源库的全部表，每行带一个复选、表名和状态胶囊（一致 / 结构(n) / n 行差异 /
  无主键 / 新表 / 全量覆写 / 已同步）。搜索框只过滤清单，不影响比对。
- **检查器**跟随左侧选中的表：`结构比对` 并排显示源与目标的 DDL 并按行标色（新增绿、删除红
  并划掉），上方先列出字段级变更摘要；`数据比对` 用「全部 / 新增 / 修改 / 删除」筛选按主键
  比出的行差异；`SQL 预览` 用只读 SQL 编辑器显示当前模式会对该表执行的脚本。
- **运行日志**在页面底部，含进度条、逐表日志和「停止」按钮；结束后刷新目标库的树缓存。

## 保存的配置

- 文件：配置目录下的 `transfers.json`（`ConfigStore::load_transfers` /
  `save_transfers`）。连接用 `ConnectionProfile::id` 记录，重命名连接不会丢配置。
- 字段：源/目标连接与库、模式、`包含 DELETE`、`仅同步目标已存在的表`、选中的表
  （未全选时保存；空表示全部）。
- 打开配置时恢复以上字段；若某个连接还没打开，会先连接，连上后自动开始比对。
- 删除使用共享确认对话框，支持多选删除。

## 四种模式

| 模式 | 结构 | 数据 | 说明 |
|---|---|---|---|
| 全部（结构+数据） | DDL | 增量 DML | 默认 |
| 仅结构 | DDL | — | |
| 仅数据 | — | 增量 DML | 无主键的表需单表启用「全量覆写」 |
| 全量传输 | DROP + CREATE | 全表复制 | 同引擎；跨引擎时改为清空目标表后复制 |

**跨引擎**（两端驱动 id 不同）只允许「仅数据」和「全量传输」：源库的 DDL 在另一个引擎上
不合法，所以结构同步被禁用，顶部提示条说明原因。此时「全量传输」不重建表，只清空目标表
再写入源表全部行，按列名对齐（不同名或缺失的列自动跳过）。

## 比对

- **结构**：两端的 `Connection::table_schema` 各取一次 `TableSchema`，用
  `rustgrid_core::sync::diff_columns` 比较列的类型、可空性、主键、自增、默认值和生成表达式。
  目标库没有该表时全部列都算新增。
- **数据**：按源表主键列读取两端全部行（`fetch_page`，每页 500 行，上限 `SYNC_MAX_ROWS` 行），
  交给 `diff_rows` 生成 insert / update / delete。主键值以 `Option<String>` 比较，`NULL` 与
  空串不同；超出上限的比对标记为「不完整」。无主键的表不做增量比对。

## 应用

每个选中且确有变更的表串行执行：

1. **结构**：`save_table_schema(target, table, target_schema, source_schema)`（新表传
   `None` 生成 `CREATE TABLE`；全量传输先 `drop_table`）。DDL 由目标驱动自己生成，跨引擎
   时直接跳过。
2. **数据**：
   - 增量：`insert_rows` / `update_rows` / `delete_rows`，每批 500 行；`选项 → 包含 DELETE`
     关掉时跳过删除。`update_rows` / `delete_rows` 的键是 `Option<String>`，`NULL` 走
     `IS NULL`。
   - 全量：先 `empty_table`（新建的表已为空则跳过），再分页 `fetch_page` + `insert_rows`
     复制源表全部行，按列名投影到目标表的列。

所有数据库调用都通过 `Runtime::spawn` 进入 Tokio；gpui 的 executor 不是 Tokio，直接 await
驱动 future 会 panic（"there is no reactor running"）。

## 选项

- **包含 DELETE 语句**：关闭后增量同步只做 insert / update。
- **仅同步目标已存在的表**：跳过只存在于源库的表（常用于「只追数据、不建表」）。
- 每张表最多比对 `SYNC_MAX_ROWS`（5000）行，超出部分在数据比对页和提示条上标注。

## 与树、标签页的关系

- 「传输」主标签是一个配置列表；连接树的选择不会再改写窗口里的源，只有 `新建传输`
  会以当前选中的库作为默认源。目标始终留空，等用户选择。
- 「传输」页拥有自己的检查器，因此右侧信息面板在该页显示为空，不会描述树里选中的表。
- 运行期间关掉子窗口会停止任务；主窗口关闭时子窗口随之关闭。日志在重新打开同一条配置后
  清空，重新比对。
